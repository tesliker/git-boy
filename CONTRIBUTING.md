# Contributing

Start with an issue describing a reproducible problem or the workflow you want to improve. Keep reports free of private repositories, credentials, customer details, and personal paths. Use a small disposable Git repository to demonstrate problems.

The native Mac app is in `Sources/GitBoy`; the early Windows review client is in `desktop`. Run the relevant tests before proposing a change. Changes must preserve unfinished work and must not add automatic pushes, destructive Git commands, or automatic transmission of repository content.

The Windows client currently reads repositories only. Do not describe it as having full feature parity with the Mac app. Downloads must clearly state their architecture, preview status, and signing status.
